# Native launcher — Rook Rainbow Quest v0.10.0

Open `dist/Play Rook Rainbow Quest.exe`, identified by a smiling cream rook on a gold/purple tile. It starts the game directly without a terminal or an extra menu. For a desktop entry, create a shortcut to this executable; keep the executable beside the release folder.

The same launcher is included in the Windows ZIP alongside `RookRainbowQuest.exe`. Extract the whole ZIP to a folder, then open `Play Rook Rainbow Quest.exe`. No installation or additional runtime is required. The game executable itself also has the new icon and remains directly playable.

The launcher first looks for its matching `RookRainbowQuest-<version>/RookRainbowQuest.exe` folder beside it, then for `RookRainbowQuest.exe` in its own folder. Paths are derived from the executable's location, not the current working directory. The launcher exits after starting the game. It never edits saves, downloads updates, uses a shell command, or requests administrator rights. Startup failures show a Windows error dialog in Swedish and English. The stable entry point is rebuilt and replaced with each validated package; it does not search for arbitrary newer executables.

The original procedural icon is generated by `scripts/make-icon.ps1` in six ICO sizes, 16–256 pixels. Source artwork uses the game's cream rook, purple outline, mint base, coral cheeks and gold/purple background. The checked-in ICO and raw RGBA sizes let ordinary builds embed it without requiring asset-generation tools. Both executables embed icon and version resources through the Windows SDK resource compiler already installed by the existing setup script. No new Cargo dependencies were added.

Validation covers the missing-file error path, publication failure preserving the previous launcher, Windows GUI subsystem, icon/version resources and actual game startup/shutdown through the repository layout, ZIP layout, another working directory, and a folder containing spaces and Swedish characters. Candidate executables are scanned before and after native validation. The old CMD entry point remains for existing shortcuts.
